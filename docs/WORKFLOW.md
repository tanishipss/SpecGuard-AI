## Running the dev servers

**Backend** (from repo root, after `alembic upgrade head` and a populated `.env`):
```
uvicorn backend.main:app --reload
```
API at `http://localhost:8000`, interactive docs at `/docs`.

**Frontend:**
```
cd frontend
npm install
npm run dev
```
Opens at `http://localhost:5173`, proxying `/api` to the backend (`frontend/vite.config.ts`).

## Ingesting a spec

Place a spec PDF under `data/` (see `data/README.md`), then:
```
curl -X POST localhost:8000/api/v1/ingest -H "Content-Type: application/json" -d '{
  "file_path": "data/23501-h70.pdf",
  "spec_number": "23.501",
  "release": "Rel-17",
  "version": "h70"
}'
```
Repeat per spec. Ingestion is idempotent per `document_hash` (sha256) — re-ingesting an unchanged file is skipped, not duplicated.

## Running tests

```
pytest tests/ -v
```
Pure-logic tests (fake LLM/DB clients injected) — no live database or API key required. Lint with `ruff check backend/ tests/`.

Frontend:
```
cd frontend
npm run lint    # oxlint
npm run build   # tsc -b && vite build
```

## Running the evaluation harness

The dataset (`evaluation/dataset.json`, 45 questions, TRD §10 categories) needs to be seeded into the live `queries` table before `/api/v1/eval/run` can score anything — the endpoint scores whatever has already been seeded, it does not run the pipeline live.

1. **Start the backend** (`uvicorn backend.main:app --reload`) and make sure the corpus is ingested.
2. **Seed dataset questions through the real pipeline:**
   ```
   python evaluation/seed_eval_queries.py
   ```
   This POSTs each `dataset.json` question to `/api/v1/chat` with its `question_id` stamped, so results land in the `queries` audit table joinable back to `dataset.json` (not by fragile text-matching).
3. **Score the seeded run:**
   ```
   curl localhost:8000/api/v1/eval/run
   ```
   Returns Citation Correctness, Hallucination Rate, Precision@5/Recall@5/MRR (only for questions with a human-confirmed `gold_sections` entry), and Ragas's Faithfulness/Answer Relevance/Context Precision. Honestly reports a `partial: true` state and the exact `scored_question_count` if fewer than 45 questions have been seeded — never presents a partial run as a finished evaluation.
4. **Run the 3-variant ablation** (Basic RAG → +Hybrid retrieval+reranking → +Full guardrails):
   ```
   python evaluation/run_ablation.py
   ```
   Writes `evaluation/ablation_results.json`, served via `GET /api/v1/eval/ablation`. This makes real LLM calls per variant per question — check the script's own cost/count output before running against the full 45-question set.

**Verifying `gold_sections` before trusting Precision@5/Recall@5:** `gold_sections` in `dataset.json` must be filled in by a human reading the actual retrieved chunk text (see `evaluation/verify_ground_truths.py` and `evaluation/review_flagged_sections.py`), never auto-populated from retrieval output — doing so would make retrieval metrics circular (scoring retrieval against itself).
